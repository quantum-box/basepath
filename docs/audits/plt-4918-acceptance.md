## スクリーンショット証跡

- **S1 ログイン画面:** CUA の in-app browser で `https://pathbase-v2.txcloud.app/login` を表示し、スクリーンショットを取得・目視確認した。PathBase の見出し、ユーザー名/メールアドレス欄、パスワード欄、Tachyon ログインボタン、認証情報を PathBase に保存しない旨を確認した。
- **S2 個人ホーム空状態:** 認証済み Chrome セッションの `/personal/home?tenant_id=tn_01kxz0ytmhnab5vh53011cwctj` を表示し、スクリーンショットを取得・目視確認した。空の目標マップ、空の今日の行動/タイムライン、最近の学び、`目標を追加` を確認した。
- **S3 組織画面:** 組織タブのアクセシビリティツリーは取得できたが、スクリーンショット API が別の個人画面と競合したため、視覚証跡としては**不採用**とした。

S1/S2 の画像バイトは CUA のツール結果として確認できたが、このサブエージェントからローカルファイルへ保存する API がなく、画像ファイルは成果物に同梱していない。シェルの `screencapture` はブラウザではなく別のデスクトップウィンドウを取得したため、不採用にした。このため「スクリーンショットをファイルで納品した」とは主張しない。

## 具体的な所見

1. 個人の空状態は、目標マップ、今日の行動、最近の学び、目標追加の入口が同じ画面にあり、空ワークスペースから開始する導線として観察できた。
2. 組織のナビゲーションは個人と異なり、`概要`、`組織の目標`、`アラインメント`、`ダッシュボード`、`目標レビュー`、`メンバー` を含み、個人の `記憶` は含まない。テナント/ワークスペース境界の UI 表現としては確認できた。
3. 組織の既存データでは、目標マップに root と展開済み子があり、選択目標の detail に成果記録、次の行動、取り組み、関連・依存関係編集、メモの操作が存在した。これは操作入口の存在の証拠であって、保存結果や権限を保証する証拠ではない。
4. S3 のようなブラウザタブ競合は監査ツールの証跡 blocker であり、プロダクト不具合とは扱っていない。

## 再現手順（今回の安全な範囲）

1. in-app browser で `https://pathbase-v2.txcloud.app/login` を開き、S1 のフォームを確認する。資格情報は入力しない。
2. 既存の認証済みセッションで `/personal/home?tenant_id=tn_01kxz0ytmhnab5vh53011cwctj` を開き、S2 の空状態を確認する。
3. 既存の組織タブのアクセシビリティツリーを確認し、組織ナビ、目標 map、選択目標 detail を読む。ライブ組織への作成・移動操作は行わない。

## Blocker / 次に必要な証跡

- 認証情報を監査側で取得できないため、認証完了・テナント選択・権限再検証は未確認。
- 空の組織、編集可能な sandbox、viewer/別テナントの permission fixture がないため、空組織、作成、任意深度、子/兄弟、Action 終端、権限エラーを安全に再現できない。
- CUA からスクリーンショットを成果物ファイルへ保存できず、ブラウザ/別アプリ選択の競合もあるため、S1/S2 はツール結果でのみ確認。視覚的な組織画面の証跡は未提出。
- 390px とキーボードは専用の再現セッションが必要。

以上より、本レポートは現時点の証拠に基づく受け入れ監査であり、未確認項目について pass や実装済みとは判定しない。
